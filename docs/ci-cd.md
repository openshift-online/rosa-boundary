## Prow: configured tests, not a universal `make check`

The editable [Boundary ci-operator config](https://github.com/openshift/release/blob/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/config/openshift-online/rosa-boundary/openshift-online-rosa-boundary-main.yaml) and [TA variant](https://github.com/openshift/release/blob/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/config/openshift-online/rosa-boundary/openshift-online-rosa-boundary-main__trusted-actions.yaml) generate the [presubmit jobs](https://github.com/openshift/release/blob/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/jobs/openshift-online/rosa-boundary/openshift-online-rosa-boundary-main-presubmits.yaml). All five generated presubmits have `always_run: false`; this **does not** justify saying every PR is tested. Check path selectors, rerun commands and actual PR contexts. Their reviewed behavior is:

| PR job (context suffix) | Command / coverage | Selection and limitation |
| --- | --- | --- |
| `coverage` | `make codecov`: root Go coverage and Enterprise Codecov upload via [script](../scripts/codecov.sh). | Marked **optional**; skips TA-only changes; does not test the TA Go module or Lambda Python code. |
| `images` | ci-operator builds the **test-runner** images (`lambda-test-runner`, `localstack-test-runner`). | Skips TA-only changes; not the Konflux shipping container or a test of its final filesystem. |
| `lambda-unit-tests` | `make test-lambda-create-investigation` (`uv run pytest test_handler.py -v`). | Skips TA-only changes; does not call the two reaper Lambda unit-test targets. |
| `localstack-integration-tests` | `make test-localstack-ci` uses [`tests/localstack/ci-run.sh`](../tests/localstack/ci-run.sh) with LocalStack Pro, nested Podman/ECS executor, JUnit and collected logs. | `run_if_changed` covers `lambda/`, `deploy/regional/`, `tests/localstack/`, `cmd/`, `pkg/`, `internal/`, root Go mod/sum and `Makefile`; requires injected LocalStack token. Emulated AWS, not real Fargate/IAM. The CI script rejects an all-skipped run, but individual skips require reading JUnit. |
| `trusted-actions-make-test` | `HOME=/tmp make -C components/trusted-actions test`: bundle/generate API, compile integration-tagged test package without running it, then `go test -v ./...` in the TA module. | `run_if_changed` covers TA files, TA HCP map and TA `.tekton/` files. Does not start Postgres, run race tests, execute the integration-tagged suite, run TA lint or verify live clusters. |

The [postsubmit](https://github.com/openshift/release/blob/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/jobs/openshift-online/rosa-boundary/openshift-online-rosa-boundary-main-postsubmits.yaml) reruns `make codecov` as `publish-coverage` after `main` changes, excluding TA-only changes; it cannot block a PR after merge. Root [`codecov.yml`](../codecov.yml) sets project/patch statuses **informational**, not a mandatory coverage threshold. The [OpenWiki config](https://github.com/openshift/release/blob/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/config/openshift-online/rosa-boundary/openshift-online-rosa-boundary-main__openwiki.yaml) defines a Tuesday/Thursday `0 16 * * 2,4` periodic whose [prepare/update/publish steps](https://github.com/openshift/release/tree/df694b879cb5470dd61e84ddddddb52e316daf1d/ci-operator/step-registry/rosa/boundary/openwiki) publish a **documentation PR**, not a GitHub Actions workflow or a functional test. No nightly real-AWS Boundary E2E job appears in the reviewed `rosa-boundary` Prow configs; that does **not** exclude jobs defined elsewhere. The scheduled OpenWiki updater has no automatic access to the private release-data repository: this document must be reviewed manually when that configuration changes.

## GitHub, infrastructure delivery and dependency updates

There are **no tracked `.github/workflows/` files** in the reviewed Boundary commit. On the review date the [GitHub Actions API for this repository](https://api.github.com/repos/openshift-online/rosa-boundary/actions/workflows) listed *dynamic* Copilot code review, Dependabot Updates, Dependency Graph and CodeQL workflows. They are service-managed entries, not YAML in this repository; their activation, scope and merge requirement need GitHub settings and run evidence. [Root](../OWNERS), [TA](../components/trusted-actions/OWNERS), [TA Terraform](../hcp-terraform/rosa-trusted-actions/OWNERS) and [Tekton](../.tekton/OWNERS) ownership files add approvers and component labels, not evidence of branch protection. [`renovate.json`](../renovate.json) configures Konflux-hosted Mintmaker/Renovate dependency PRs; its configured managers and automerge exceptions are not proof that the hosted updater ran. See [dependency management](dependency-management-automation.md).

The two [Boundary](../hcp-terraform/rosa-boundary/main.tf) and [TA](../hcp-terraform/rosa-trusted-actions/main.tf) meta-workspace definitions point to this GitHub repository but own separate HCP projects/states. In Boundary's twelve L3 workspaces, three explicitly set `auto_apply = false` (stage credentials, stage east network, prod credentials) and nine set `true`; both TA workspaces declare `true`. A same-repository PR can produce HCP speculative plans, but a fork PR may not; the L2 meta-workspace plan only shows workspace configuration and variables, **not the downstream AWS plan**. On merge, a workspace run may apply automatically depending on its effective settings and success. A successful Konflux release does **not** switch an ECS/Lambda version: the Git-managed image pin must be changed, reconciled by the meta-workspace, then applied by the target workspace. See [staging delivery](staging-deployment.md) for the ordered procedure. Check actual HCP runs, registry presence, image digests and target account/Region before concluding deployment succeeded.

## Local gates and what they leave untested

- [`make test`](../Makefile) runs root Go coverage, all three Lambda Python unit suites, build-helper pytest and Bats shell regressions. `make check` adds Go lint (golangci-lint or `go vet` fallback), strict ShellCheck, Staticcheck and pre-commit; it can rewrite files. None of these automatically starts LocalStack. `make test-coverage` creates root Go coverage without Codecov upload.
- [`make test-all`](../Makefile) / [`scripts/test_all.py`](../scripts/test_all.py) collects logs for local unit tests, Python/JUnit, formatting/lint, Terraform fmt/init/validate and **mock-provider** Terraform tests in a disposable snapshot, LocalStack integration, root multi-architecture image and Lambda image builds, and pre-commit. It needs an already-running LocalStack; `TEST_ALL_ARGS=--require-complete` rejects skipped tests. LocalStack and mocked Terraform do not prove deployed AWS enforcement. The [Prow-oriented LocalStack entrypoint](../tests/localstack/ci-run.sh) starts its own task-capable Podman executor and rejects all-skipped results; do not equate that with the default local executor.
- [`.pre-commit-config.yaml`](../.pre-commit-config.yaml) configures always-run skillsaw, whitespace/EOF/YAML/size/merge checks, root golangci-lint **excluding TA**, gitleaks **only for TA**, and a TA Go build when TA Go/module files change. `make pre-commit` runs all hooks through `uv`; this is not a full test suite or a root-wide secret scan. TA's [own Makefile](../components/trusted-actions/Makefile) has separate `make test` (generates OpenAPI code, compiles an integration-tagged package, then tests its Go module), plus opt-in lint, race, Postgres, API, kind/ministack, coverage and release-build targets. Root `go test ./...` and root Make targets do not traverse TA.
- [Boundary Terraform test suites](../deploy/account/tests/) and [regional tests](../deploy/regional/tests/) mock AWS; the [Python replication-topology check](../deploy/account/tests/test_replication_topology.py) is separate. Neither the reviewed Prow targets nor Konflux PipelineRuns run root `make check`, the full `make test-all`, all Terraform tests, both reaper unit-test targets, TA Postgres/race/integration, final shipping-image tool acceptance via `make verify-image-tools`, or a live SRE investigation in AWS. Codecov's configured informational statuses are not a TA coverage requirement. In-boundary OIDC/ECS Exec, credentials, EFS, CloudWatch/S3 audit and actual regional delivery need approved live verification with cleanup and evidence.
