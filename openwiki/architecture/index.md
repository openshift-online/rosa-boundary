# Files

- [Identity and Access Architecture (Boundary)](identity-and-access.md) - Explains Boundary's identity model — Keycloak OIDC federation into AWS IAM roles for CLI/Lambda/ECS Exec, GitHub OIDC federation for content publishing, and the account-wide shared-iam Terraform module that issues every one of these identities.
- [Monorepo components: Boundary and Trusted Actions](monorepo-and-trusted-actions.md) - Explains how the ROSA Boundary and Trusted Actions (TA) products co-exist as independently owned and built components in the `rosa-boundary` repository after the Trusted Actions monorepo migration, and what the 2026-11-11 migration record does and does not establish about current live systems.
- [ROSA Boundary System Overview](system-overview.md) - Maps the ROSA Boundary Go CLI and control-plane code layout, the ephemeral SRE investigation container on ECS Fargate, the Lambda-based investigation lifecycle, and the Terraform stacks that wire them together, and situates this flow relative to the co-located but independently built/deployed Trusted Actions component.
- [Trusted Actions Authentication and Authorization](trusted-actions-authorization.md) - Explains the Trusted Actions request pipeline's auth chain — JWKS-backed OCM JWT authentication, account-JWT middleware, audit logging middleware, API-level role authorization, and per-action access checks — plus the separate resource-level authorization performed inside the executor, and how auth is skipped for health checks and mock/dev mode.
- [Trusted Actions architecture](trusted-actions-overview.md) - Explains Trusted Actions' two-layer architecture (HTTP request handling vs. asynchronous action execution), its Go module/CLI layout, its own container image, and the plugin model for adding new actions.
