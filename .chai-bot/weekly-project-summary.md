You will create a thorough summary of the state of the
rosa-boundary project. This is a weekly report, so highlight
specifically the changes made within the past week (7-day
lookback), but also provide overall project status context.

Post the report in the working group slack channel.

Audience: Engineering leadership AND the engineers currently
working on the project. Focus on progress, blockers, issues,
and future work rather than deep technical details. Be concise
— prefer short descriptions and link to artifacts (Jira
tickets, PRs, GitHub issues) for details.

Separate the report into these sections:

1. Recent Accomplishments — Work completed or merged in the
   past 7 days. Link to PRs, Jira tickets, or commits.

2. New Issues — Newly created Jira issues or GitHub issues,
   AND any problems surfaced in Slack discussions that may not
   yet have a tracking ticket. For untracked issues, call them
   out explicitly so they can be ticketed.

3. In-Progress — All open/in-progress work items. Highlight
   any items with no recent activity (stale items). Flag
   blockers.

4. Immediate Next Steps — Infer logical next steps based on
   the current state of the project, open items, and recent
   discussions. Include both documented next steps and your
   assessment of what should come next.

Formatting rules:
- No more than 80 lines total, prefer less.
- Bold the most important bits so someone skimming catches the
  key points.
- Be concise — short descriptions with links, not lengthy
  explanations.

Resources to review:
- Top-level Jira Initiative:
  https://redhat.atlassian.net/browse/ROSA-738
- Working group channel: #wg-rosa-boundary (C0B9BKW9T7V)
- Public GitHub repository:
  https://github.com/openshift-online/rosa-boundary

Scope exclusions:
- Strictly exclude the trusted-actions project, even if
  discussed in the same channel. These projects are related
  but tangential.
